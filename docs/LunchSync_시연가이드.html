1한 줄 소개 & 핵심 가치

LunchSync는 "점심 뭐 먹지?"의 결정 피로를 없애는 앱입니다. 팀원이 세션을 만들고, AI 추천·투표·이상형 월드컵으로 식당을 함께 결정한 뒤, 앱에서 바로 주문·결제·픽업 추적까지 끝냅니다. 사장님은 전용 앱/POS로 주문을 받고 매출을 관리합니다.

차별점 3가지
  • 함께 결정 — 혼자 고민이 아니라 팀이 투표·토너먼트로 재미있게 결정
  • 결정→주문→픽업 한 번에 — 더치페이 자동 계산까지 한 흐름
  • 위치 기반 실데이터 — 카카오·네이버 크롤 + AI 폴백으로 어느 동네든 후보 확보

2시연 전 체크리스트 (가장 중요!)

  • 네트워크: 핸드폰 핫스팟 사용 (공용 와이파이 X — 스타벅스/학교 와이파이는 캡티브 포털이라 끊김)
  • 앱 설치 확인 — 폰에 설치되어 AWS 서버(EC2)에 연결됨 (USB 불필요, 폰 단독 작동)
  • 로그인 상태 — 카카오 로그인 또는 시연용 시드 로그인 FAB
  • 백엔드 살아있는지 — 홈에 식당/세션이 뜨면 정상
  • 2대 분리 시연 — 폰=손님(카카오), 다른 기기=사장(시드 로그인)으로 계정 분리
  • 결제는 토스 테스트 키 — 실제 결제 안 됨 ("테스트 환경이에요" 표시)
💡 네트워크 안전장치
모든 API가 일시 끊김 시 자동 재시도(2~3회)하도록 보강됨 — 핫스팟이 깜빡여도 "후보 0개" 오류 대신 자동 복구. 그래도 안정적인 핫스팟 권장.

구성기술역할

핵심 원칙: Flutter → NestJS HTTP API만 호출 (Supabase 직접 접근 금지) · 실시간은 3초 폴링 + HTTP 304.

4시연 시나리오 (3-흐름)

🙋 손님
  1. 로그인 → 홈
  2. 세션 만들기·초대
  3. AI추천/투표/토너먼트로 결정
  4. 메뉴 담기→결제
  5. 픽업 추적→별점
🧑‍🍳 사장
  1. OWNER 로그인
  2. 주문 접수·상태 진행
  3. 음식 사진·오늘의 한 줄
  4. 메뉴 관리
  5. 매출·단골 통계
🖥️ POS
  1. 좌석 관리
  2. 예약·대기
  3. 주문 접수
  4. 결제·환불 시뮬
  5. 본사 실시간 연결

손님 흐름 상세 (메인 시연)

  1. 로그인 → 홈 ("안녕하세요, OOO님!") — 오늘의 세션·AI추천·인기 식당 표시
  2. 세션 만들기 → 이름·반경·예산·복귀시간 입력 (방장 자동 참여)
  3. 친구 초대 → 8자리 코드/링크 공유 (24h 만료)
  4. 식당 결정 → AI추천+투표 / 이상형 월드컵(8강→결승) / 룰렛·사다리 중 선택
  5. 메뉴 담기 → 주문 검토 → 토스 결제위젯(카드·계좌·간편결제) → 완료
  6. 주문 추적 → 3초 폴링 실시간 상태 + 예상 픽업시간 + 사장님 사진 + 더치페이
  7. 별점·리뷰 → 픽업 완료 후 작성 → 다음 추천 반영, 단골 등급 토스트

5핵심 기능 상세

① AI 추천 엔진

위치(반경)·예산·알레르기/취향·최근 식사 이력을 종합한 점수 추천. 최근 3일 방문은 강한 회피(-20점), 7일 내 -10점 → "최근에 다녀왔어요" 배지.

② 이상형 월드컵 토너먼트 (WOW#6)

후보 8개 셔플 → 8강→4강→결승 1:1 대결. 우승은 홈 "이번 주 인기 식당"(트렌딩, WOW#9)에 반영.

③ 주문 추적 & 더치페이

3초 폴링 실시간 갱신. 2명 이상이면 1인당 금액 자동 계산 → "카톡에 보내기" 공유.

④ 식당 데이터 3단 수집

카카오 로컬 → 네이버 플레이스(메뉴·평점) → Gemini AI 추정 → 카테고리 라이브러리. 어느 동네든 채워짐.

⑤ 안정성 (최근 보강)

모든 API 호출 자동 재시도(일시 오류·타임아웃 2~3회 백오프). 공용망 깜빡임에도 화면 안 깨짐.

6예상 질문 & 답변

추천은 어떤 기준인가요?
위치 반경·1인 예산·멤버 알레르기/취향·최근 식사 이력(중복 회피)을 종합한 점수 기반입니다.
실시간 동기화는 소켓인가요?
안정성을 위해 WebSocket 대신 3초 폴링 + HTTP 304(변경 없으면 본문 미전송)를 씁니다.
결제는 진짜 돈이 나가나요?
아니요. 토스 테스트 키라 UI는 실제와 같지만 실결제는 안 됩니다.
식당 데이터는 직접 입력했나요?
카카오+네이버 크롤로 실제 식당·메뉴·평점 수집, 없는 지역은 Gemini AI·카테고리 폴백.
손님앱·사장앱이 따로인가요?
단일 앱에서 role(CUSTOMER/OWNER) 분기. POS(LSPOS)만 매장 단말용 별도 앱입니다.
폰 2대 동시 시연은?
같은 카카오 계정은 role이 양쪽에 영향 → 시연용 시드 로그인으로 한쪽을 다른 계정(사장)으로 분리.
네트워크가 끊기면?
자동 재시도로 복구합니다. 그래서 개인 핫스팟 권장, 토너먼트는 통신오류와 "후보 없음"을 구분 표시.
보안은?
NestJS가 모든 권한 검증(JWT·본인 주문만·POS는 자기 매장만·초대코드 8자리+24h). Supabase는 백엔드로만 접근.
