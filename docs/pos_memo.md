## 1. 식당앱(런치싱크) 기능

**목적:** 사용자에게 식당/메뉴/가격 정보를 보여주기 위한 기본 데이터 확보

- AI 크롤링으로 식당 **20~30개 기본 정보 수집**
- 수집 대상:
    - 식당명
    - 위치
    - 메뉴명
    - 가격
- 서버 DB에 저장
- 저장 시 식당마다 **고유번호(restaurant_id)** 부여
- 이후 식당앱에서는 서버에 저장된 식당/메뉴 정보를 사용자에게 조회용으로 제공

---

## 2. POS 기능

**목적:** 매장 운영 관리

- 식당 등록 시 발급받은 **고유번호로 식당 연동**
- 고유번호 기반 로그인
- 메뉴 / 가격 수정
- 주문 접수 처리
- 좌석 예약 / 좌석 선택 관리
- 하루 전체 매출 확인
- 결제 수단별 관리
    - 현금
    - 카드

---

## 3. 사장앱 기능

**목적:** 점주가 식당 정보 등록 및 운영 정보 확인

### A. 등록 안 된 식당일 때

- 사장과 계약 후 앱 사용 시작
- 식당 등록
- 내 업체 선택
- 고유번호 발급
- 기존 인터넷 데이터 불러오기
    - 메뉴
    - 가격
    - 위치
- 서버 DB 저장
- 점주가 직접 메뉴 / 가격 수정

### B. 이미 로그인된 식당일 때

- 로그인
- 메뉴 / 가격 수정
- 예약 건수 확인
- 하루 매출 확인

---

## 4. 권한 정리

### 식당 정보 등록

- **사장앱에서만 가능**

### 메뉴 정보 등록 / 수정

- **사장앱, POS 둘 다 가능**

---

## 5. 예외처리: 크롤링 정보와 사장 수정 정보가 다를 때

이건 **최종 우선순위**를 정해두면 됨.

### 추천 방식

- **사장 수정 정보 우선**
- 크롤링 데이터는 **초기 자동 입력용**
- 점주가 한 번 수정하면 해당 값이 **최신 공식 정보**가 됨

### 처리 규칙

- 최초 등록 전: 크롤링 정보 사용
- 사장이 수정 후: 사장 정보로 덮어쓰기
- 이후 AI 재크롤링 시:
    - 자동 반영하지 않음
    - “변경 후보 데이터”로만 비교
    - 관리자 승인 또는 점주 확인 후 반영

### 한 줄 정리

- **크롤링 = 초안 데이터**
- **사장 수정 = 최종 데이터**

# 2. 프로젝트 개요

## 2-1. 프로젝트명

LunchSync

## 2-2. 서비스 개념

LunchSync는 식당 정보 확인, 메뉴 선택, 웨이팅, 예약, 주문을 하나로 연결하는 식당 운영 플랫폼이다.

# 3. POS의 역할

POS는 식당에서 실제로 사용하는 포스기처럼 주문 접수, 테이블 관리, 메뉴 관리, 결제 처리, 매출 확인을 담당한다.

단순 관리자 페이지가 아니라, 식당 직원이 매장에서 바로 사용할 수 있는 운영 화면이어야 한다.
