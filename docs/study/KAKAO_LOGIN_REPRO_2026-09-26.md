# 카카오 로그인 장애 조사와 로컬 수정

날짜: 2026-09-26
대상: `agent/reliability-observability` 로컬 작업 트리

## 실제 확인한 사실

- Flutter의 기본 API는 `https://lunchsync-api.duckdns.org/api`다. 공개 `/health`는 응답하지만 `/ready`는 404이며, 배포 서버의 이메일 OTP 응답 계약은 현재 로컬 NestJS 코드와 다르다. 따라서 최신 앱 코드와 서버가 함께 배포된 상태로 볼 수 없다.
- Kakao Developers의 새 LunchSync 앱(1534395)은 카카오 로그인 `ON`이다. 앱의 JavaScript/Native 키, Android 패키지 `com.whh07151.lunchsync`, 디버그 APK의 키 해시는 콘솔 등록값과 일치한다.
- JavaScript SDK 허용 도메인은 `http://localhost:8080` 하나다. 이때 테스트에 사용한 `http://127.0.0.1:8041`은 다른 호스트와 포트라 로그인 완료를 검증하는 주소로 사용할 수 없다. 이 주소에서 SDK 인증 팝업까지는 열렸지만 사용자의 개인정보 동의는 진행하지 않았다.
- 현재 연결된 Supabase 개발 프로젝트의 `public.users`는 0건이다. 이는 그 프로젝트의 기존 이메일 로그인 실패를 설명하지만, 카카오는 신규 사용자 생성 경로이므로 카카오 실패의 단독 원인으로 볼 수 없다. 배포 서버가 동일 프로젝트를 사용하는지도 확인되지 않았다.
- 첫 실행 화면의 `카카오로 시작하기`는 실제로 로그인 방식 선택 화면으로 이동했고, `먼저 둘러볼게요`는 준비 중 화면에서 막혔다. 백엔드 카카오 로그인에서 4xx/5xx가 와도 앱은 모두 `서버 연결에 실패`로 표시했다.
- Android x86_64 에뮬레이터에 새 APK를 설치해 첫 화면 → 로그인 화면 → 카카오 계정 페이지(`accounts.kakao.com`)까지 실제 진입했다. 카카오 계정 페이지를 닫으면 SDK가 `PlatformException(code: CANCELED)`를 반환했고, 수정 전 앱은 이를 일반 로그인 실패로 표시했다. 로그인 완료는 진행하지 않았다.

## 로컬 수정

- 첫 화면을 `로그인·회원가입` 단일 진입으로 정리하고 미구현 둘러보기 분기를 제거했다.
- SDK의 사용자 취소·플랫폼 미등록·앱 키 오류를 구분해 안내한다. Android/iOS의 `PlatformException(code: CANCELED)`도 사용자 취소로 처리하며, 취소 시 오류 스낵바를 표시하지 않는다. 카카오톡 로그인 취소 후 웹 인증을 자동으로 다시 열지 않는다.
- 카카오 로그인 CTA를 표준 버튼으로 바꿔 키보드 포커스와 Enter/Space 조작을 지원한다.
- 서버의 카카오 로그인 오류 본문을 앱에 전달하고, 네트워크 오류 및 앱·서버 응답 계약 불일치를 따로 안내한다. 토큰과 계정 정보는 로그에 출력하지 않는다.
- 합성 토큰을 사용하는 단위 테스트로 서버 401, 정상 로그인 응답, SDK 오류 분류와 첫 화면에서 로그인 화면으로의 이동을 검증했다. 수정 전용 5개와 전체 Flutter 30개 테스트가 통과했고 정적 분석 오류는 없었다.
- `flutter build web --no-pub --dart-define=BACKEND_URL=https://lunchsync-api.duckdns.org/api`가 통과했다. 생성된 `main.dart.js`가 `http://localhost:8080`에서 HTTP 200으로 제공되는 것도 확인했다.
- `flutter build apk --debug --split-per-abi --no-pub`가 통과했다. x86_64 APK는 약 74MB, 패키지명은 `com.whh07151.lunchsync`, 서명 키 해시는 Kakao Developers에 등록된 디버그 값과 일치한다. 이전 `com.example.capstone` 설치와 별개 앱이다.
- Android 실제 화면 증거: `D:\취업하자\테스트증거\LunchSync\06_안드로이드_시스템UI복구.png`(첫 화면), `07_안드로이드_로그인화면.png`, `09_안드로이드_카카오로그인.png`, `10_안드로이드_카카오취소.png`(수정 전 취소 오류). 에뮬레이터 부팅 직후 System UI 응답 없음 알림은 해당 시스템 앱을 닫은 뒤 사라졌으며 LunchSync 화면은 정상 표시됐다.
- 수정 APK를 재설치해 동일한 카카오 창 닫기 흐름을 다시 시험했다. `D:\취업하자\테스트증거\LunchSync\13_안드로이드_카카오취소수정후.png`에서 로그인 화면으로 복귀하고 실패 알림이 뜨지 않는 것을 확인했다.
- 개발용 시드 계정 버튼은 `kDebugMode`에서만 노출하도록 변경했다. 실제 계정 로그인 성공 검증과 별개로 배포 화면에 시연 버튼이 보이지 않도록 한 조치다.
- 최종 변경 후 전체 Flutter 테스트 30개, 변경 파일 정적 분석, 웹 빌드와 ABI별 Android 디버그 APK 빌드가 다시 통과했다. 웹 `http://localhost:8080/main.dart.js`는 새 산출물을 HTTP 200으로 제공한다. 최종 x86_64 APK를 에뮬레이터에 재설치하고 카카오 계정 창 열기·닫기를 반복했으며, `D:\취업하자\테스트증거\LunchSync\17_최종APK_카카오취소.png`에서 오류 알림이 없고 이 과정의 `KakaoAuth` 실패 로그도 0건이었다.

## 남은 실제 로그인 검증

1. 웹이라면 AcademyFlow와 포트 충돌을 피한 뒤 LunchSync를 **`http://localhost:8080`**에서 실행한다. 앱은 `--dart-define=BACKEND_URL=https://lunchsync-api.duckdns.org/api`를 지정한다. Android라면 `com.whh07151.lunchsync` 새 패키지 APK로 실행한다.
2. 카카오 동의 화면의 최종 동의는 사용자가 직접 확인한다. 이 단계 전후의 앱 화면 오류와 서버 HTTP 상태를 비교한다.
3. 운영 서버는 로컬 앱과 인증 응답 계약이 맞지 않으므로, 배포하기 전 비운영 환경에서 백엔드·Flutter를 같은 리비전으로 실행해 가입→로그인→자동 로그인 흐름을 확인한다.
4. 원격 배포, Supabase 데이터 변경, 플랫폼 허용 도메인 추가는 이 조사에서 실행하지 않았다.

이 문서는 실제 카카오 계정의 로그인 성공을 주장하지 않는다. 현재 확인된 것은 콘솔 설정, 테스트 주소 불일치, 배포 버전 차이와 로컬 오류 처리 개선이다.
