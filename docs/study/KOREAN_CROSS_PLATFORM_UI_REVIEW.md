# LunchSync 한국어 크로스플랫폼 UI 검토

## 이번 변경의 사용자 문제

LunchSync의 손님 화면은 이미 한국어 중심이지만, 홈 첫 화면에서 빠른 실행
4개가 오늘 참여할 세션보다 먼저 보였다. 휴대전화에서는 4개 버튼을 한 줄에
고정해 터치 영역과 글자 폭도 좁았다. 사용자가 앱을 열자마자 해야 할 일보다
기능 목록을 먼저 해석해야 하는 구조였다.

## 적용한 정보 계층

홈 첫 화면의 순서를 다음처럼 고정했다.

1. 사용자와 소속 맥락
2. 오늘의 점심 세션과 실제 상태
3. 점심 만들기·코드 참가 등 빠른 실행
4. 즐겨찾기·토너먼트·추천 식당

세션과 빠른 실행은 `HomePrimaryLayout`으로 분리했다. 760px 미만에서는 세션이
먼저 나오는 단일 열이고, 그 이상에서는 실제 웹 폭을 활용해 두 영역을
나란히 보여 준다. 빠른 실행은 620px 미만에서 2열, 그 이상에서 4열로
바뀐다.

## 시각·상호작용 결정

- 인사 영역은 장식용 그라디언트 대신 LunchSync의 주황 단색과 점심 아이콘을
  사용했다.
- 영문 소제목이나 반복되는 설명 문구 대신 `오늘의 점심 세션`, `바로가기`처럼
  사용자가 익숙한 짧은 한글 제목과 얇은 주황색 기준선을 사용했다.
- `점심 만들기`와 `코드로 참가`는 실제 세션 진입에 가까운 주 행동으로
  강조하고, 최근 이력과 토너먼트는 보조 행동으로 구분했다.
- 빠른 실행은 `GestureDetector`가 아니라 `Material`과 `InkWell`을 사용해
  웹의 키보드 포커스와 눌림 피드백을 보존했다.
- 화면낭독기가 인사 영역과 빠른 실행을 각각 헤더와 버튼으로 이해하도록
  의미 정보를 추가했다.
- 런타임에는 기존 세션·사용자·식당 API 결과만 사용했다. 데모용 식당이나
  성공 상태를 새로 만들지 않았다.

## 웹·앱 범위

이 변경은 Android, iOS, Chrome 웹이 공유하는 Flutter 위젯에 적용된다.
네이티브 데스크톱 앱을 새로 만들거나 기존 POS 준비 상태를 출시 완료로
간주하지 않는다. 결제·인증·백엔드 동작은 이번 UI 범위에서 변경하지 않았다.

## 검증

```powershell
cmd /c C:\flutter\bin\flutter.bat test test\home_primary_layout_test.dart --no-pub --reporter expanded
cmd /c C:\flutter\bin\cache\dart-sdk\bin\dart.exe analyze --fatal-infos
git diff --check
```

위젯 테스트는 390px에서 세션이 빠른 실행보다 먼저 배치되는지, 1000px에서
두 영역이 나란히 배치되는지를 확인한다. 전체 정적 분석과 기존 테스트 결과는
작업 인계 문서에 실제 실행 결과 그대로 기록한다.
